# ADR 0093 — Release-signed CRITICAL_MODULES manifest is the integrity trust root

- **Date (UTC):** 2026-11-02
- **Authors:** Fabio Leitao
- **Deciders:** Fabio Leitao

## Status

Proposed

### Status history

- 2026-11-02 — Proposed — records the trust-root change for [#2168](https://github.com/DataBoar/data-boar/issues/2168).

## Context

The SQLite integrity anchor (#856) and the later local upgrade paths (#1262 operator reconcile, #2165 wheel `RECORD` match) decided `validated` / `expected` from state that lives next to the installed tree. That class of check cannot prove release origin. [#2168](https://github.com/DataBoar/data-boar/issues/2168) requires a fail-closed trust root: a CRITICAL_MODULES hash manifest signed at release time, verified offline with a public key already packaged in the product.

New keys are out of scope. The repository already ships an Ed25519 license verify key (`core/licensing/license-pub-v1.pem`) and a TTY issuer private-key path for license signing. SSHSIG / `allowed_signers` remains available for gate attestation, not for this runtime check.

## Decision

1. **Trust root** — `validated` / `expected` only when installed `CRITICAL_MODULES` hashes match a packaged manifest (`core/licensing/integrity_manifest.json`) whose Ed25519 signature verifies with the existing license public key (`load_embedded_official_public_key_pem`).
2. **Fail closed** — absent, unreadable, unsigned, wrong-key, hash-mismatched, or downgrade trees are `tampered` / `adulterated`. Unsigned 1.8.0-class checkouts are not `validated` by omission.
3. **SQLite is forensic** — `build_integrity_anchor` and `integrity_events` record last-seen signed label and append-only events. They do not mint trust.
4. **`--reconcile-integrity-anchor`** — CLI flag stays for compatibility. It records a `reconcile` event and re-evaluates the same signed manifest. It cannot produce `validated` by itself.
5. **Signing** — operator TTY only, via `scripts/sign-integrity-manifest.py`, using the existing license issuer env vars. CI may run `--verify-only` (public key). No private key in CI, no new key material generated by this work.
6. **Key recommendation** — reuse the packaged license Ed25519 verify key (already distributed, offline). **Alternative considered:** SSHSIG over `docs/adr/allowed_signers`. Rejected for this runtime path: the license verify loader is already in-process and does not add a second public-key channel.
7. **Self-inclusion (ADR 0088)** — `core/integrity_signed_manifest.py` is in `CRITICAL_MODULES`. Replacing the packaged public key is outside what this check proves.

## Consequences

- First signed release must write `core/licensing/integrity_manifest.json` on the operator TTY and include it in the wheel (`force-include` when the file exists).
- Trees without that file stay tinted (`-alpha`) until a matching signed manifest is present.
- #2165 `RECORD` auto-rebaseline is superseded as a trust root. The merged PR remains history; this ADR replaces that mechanism.
- Honest limit: this proves match to a manifest signed by the packaged verify key. It does not prove physical or nation-state resistance.
