## Changed patterns (copied faithfully from `CHANGELOG.md` § `## Unreleased`)

The following 4 pattern changes, originally documented in the `## Unreleased` section of `CHANGELOG.md`, are now finalized in the `1.8.0` release notes:

### licença híbrida obrigatória #2042

Enforced mode rejects a token that has no `dbmldsa_sig` (`hybrid_claim_required`) and rejects verification when the packaged ML-DSA anchor is missing (`missing_mldsa_anchor`). Ed25519-only licenses from 1.7.4 must be reissued before an enforced 1.8 deployment. `licensing.mode: open` is unchanged.

### `GET /health` reduzido #2077

The unauthenticated body is only `{"status":"ok"}`. License, trust, transport, and integrity moved to authenticated `GET /status`.

### nomes reservados de credencial #2086

A name this process reserves for itself is refused as a target credential. The public prefix list is unchanged. Names outside the `DATA_BOAR_` / `REST_API_` / `API_` prefixes, or when the destination is missing from that target's `allowed_hosts`, fail at load. Shipped examples now use prefixed names (`DATA_BOAR_DEMO_DB_PASSWORD`, `DATA_BOAR_LAB_*`). `pass_from_env` fails at load when the name is outside the allowed prefixes or the destination is missing.

### host gate fail-closed #2103

An env credential fails closed unless the process sets `DATA_BOAR_CREDENTIAL_ALLOWED_HOSTS` (comma-separated hosts, no port). YAML `allowed_hosts` only narrows that list. Lab opt-out: `DATA_BOAR_CREDENTIAL_HOSTS_UNRESTRICTED=1` logs a warning and restores the previous YAML host gate.

### Amex Diners fora do 1.8.0, tratados na #1984 (v1.8.1)

- **Payment card numbers in free text:** built-in **`CREDIT_CARD`** detection targets **16-digit** PAN shapes (4-4-4-4, including TAB/NBSP separators per **#1978**). **Luhn-valid Amex (15-digit) and Diners (14-digit)** strings in unstructured content are **not** matched by that regex today; when the **PCI sample override** (`PCI_CARD_COLUMN` in `docs/compliance-samples/compliance-sample-pci_dss.yaml`) is configured, **named** card columns may still be flagged. Remediation tracked for **v1.8.1** (**data-boar#1984**), not a blocker for this release.

## Limitações

O que **não está provado** para a 1.8.0:

- **Smoke do RC:** executado em 22/out/2026 pelo harness do Maestro (perfil `benchmark-rc-v3`, 4 hosts do laboratório). O pacote mínimo de evidência não ficou completo: o SHA do Boar por host e o `session_id` com `status=completed` não foram registrados no log. As falhas da rodada viraram achados do Maestro (DataBoar/maestro#108–#112); as correções de #108–#110 já estão mescladas (DataBoar/maestro#114).
- **Completão nos hosts:** não é verde. latitude FAIL:2, t14 FAIL:3, alpine FAIL:1 (alpine never ran the scan).
- **Atestação de proveniência:** o `release-manifest.json` anexado a esta Release foi regravado pelo workflow de pacotes nativos depois da atestação e **não** passa em `gh attestation verify`; os SBOMs (`sbom-python.cdx.json`, `sbom-docker-image.cdx.json`) e o `build-digest.txt` passam. O passo de anexar foi corrigido (DataBoar/data-boar#2159) e vale a partir da próxima release (#2158).
- **Problema conhecido (bug):** ao atualizar uma instalação que já tem um SQLite com a âncora de integridade de uma versão anterior, o runtime exibe `INTEGRITY TAMPER DETECTED` e se marca `-alpha` até a âncora local ser reconciliada com `data-boar --reconcile-integrity-anchor --confirm-upgrade-to=1.8.0`. Os arquivos instalados não foram alterados (conferem com o `RECORD` do wheel). Rastreado na issue #1262. Em instalação nova a âncora é criada na primeira execução.
- **Paridade e desempenho vs 1.7.4:** ainda não medidos.
